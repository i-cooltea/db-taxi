## Context

DB-Taxi 是一个 MySQL 数据同步工具，当前架构为 Go (Gin) 后端 + Vue 3 前端。后端已有完善的连接管理（`internal/sync/`）、数据库元数据查询（`internal/database/schema.go`）和批量数据处理能力。前端基于 Vue Router + Pinia 管理状态，已有 Connections、SyncConfig、Monitoring、ConfigManagement 四个页面。

用户在同步表之前缺少一种手段来了解源表和目标表的差异，容易造成错误覆盖或遗漏。需要新增表对比功能，复用现有连接管理体系，在同步前提供差异可视化。

## Goals / Non-Goals

**Goals:**
- 支持用户选择任意两个连接下的任意两张表进行结构和数据差异对比
- 结构对比：检测列的新增、删除、类型变更
- 数据对比：检测仅存在于源/目标的行、列值不同的行（基于主键匹配）
- 前端提供清晰的差异展示界面，支持结构差异和数据差异切换
- 大表数据对比采用分页/采样策略，避免内存溢出

**Non-Goals:**
- 不支持无主键表的数据差异对比（结构对比仍可用）
- 不支持跨数据库类型对比（仅限 MySQL → MySQL）
- 不做自动冲突解决或自动同步（仅查看差异）
- 不支持索引、外键、触发器等除列以外的结构差异对比（首期）

## Decisions

### 1. 后端：在 `internal/sync/` 下新增 `diff_engine.go`
**选择**: 在 sync 包内新增 diff engine，而非新建独立包。
**理由**: diff 需要复用 connection manager 获取远程数据库连接，且 diff 是同步流程的自然前置步骤，放在同一包内可共享 repository 层数据访问逻辑。独立包会增加跨包依赖复杂度。
**备选**: 新建 `internal/diff/` 包 — 拒绝，因为会导致循环依赖或大量跨包调用。

### 2. API 设计：RESTful 端点挂在 `/api/sync/diff/` 下
**选择**: `POST /api/sync/diff/compare` 执行对比，`GET /api/sync/diff/:id` 获取结果。
**理由**: 对比操作可能耗时较长（大表），采用异步模式：发起对比返回 task ID，前端轮询或 SSE 获取结果。与现有 job 模式一致，用户体验统一。
**备选**: 同步接口直接返回结果 — 拒绝，大表对比可能超时。

### 3. 结构对比算法：列名全量比对
**选择**: 以列名为 key，分别从源表和目标表获取 `SHOW COLUMNS` 结果，按列名做集合差集和交集。
**理由**: 简单直接，列名在 MySQL 表内唯一。交集列再比对类型、是否允许 NULL 等属性差异。
**备选**: 基于列序号比对 — 拒绝，列序号不具语义，重命名列会误判。

### 4. 数据对比算法：主键 JOIN + 哈希对比
**选择**:
1. 获取两张表的主键列
2. 对源表和目标表做 FULL OUTER JOIN（MySQL 用 LEFT JOIN + RIGHT JOIN 模拟）
3. 对匹配行计算所有非主键列的 MD5 哈希进行值比对
4. 分类结果为：only_in_source、only_in_target、value_diff

**理由**: 基于 SQL 的 JOIN 在数据库层执行，利用索引性能好；MD5 哈希避免传输完整行数据。
**备选**: 逐行拉取到应用层对比 — 拒绝，网络开销大，大表不可行。

### 5. 大表策略：分批对比 + 行数限制
**选择**: 数据对比默认限制最大对比行数（可配置，默认 500 行），超过时仅对比前 N 行并提示用户。分批查询避免单次查询内存溢出。
**理由**: 实现简单，覆盖大多数场景。完整对比大表需要流式处理，复杂度高且首期非核心需求。
**备选**: 流式游标对比 — 推迟到后续迭代。

### 6. 前端：新增 `TableDiff.vue` 页面 + 路由
**选择**: 在前端新增独立的 `/diff` 路由和 TableDiff 视图，复用现有连接选择组件模式。
**理由**: 对比功能逻辑独立，不适合嵌入已有同步配置页面。独立页面清晰且可扩展。
**组件结构**:
- 选择区域：左侧选源表，右侧选目标表（连接+数据库+表三级选择）
- 结果区域：Tab 切换结构差异 / 数据差异
- 结构差异：表格展示，颜色标识新增(绿)/删除(红)/变更(黄)
- 数据差异：表格展示差异行，支持分页

### 7. 结果导出：JSON 格式
**选择**: 对比结果支持导出为 JSON 文件。
**理由**: JSON 格式通用，结构化程度高，方便后续处理。前端直接下载。
**备选**: CSV 导出 — 数据差异是嵌套结构，CSV 不适合，后续可追加。

## Risks / Trade-offs

- **[大表对比性能]** → 分批策略 + 行数上限缓解，提示用户部分对比结果
- **[无主键表不可对比数据]** → 前端明确提示，仅提供结构对比
- **[跨连接网络延迟]** → 异步任务模式避免前端超时，复用现有连接池
- **[MySQL 版本兼容性]** → `SHOW COLUMNS` 和 `SHOW INDEX` 为标准 SQL，兼容 MySQL 5.7+
